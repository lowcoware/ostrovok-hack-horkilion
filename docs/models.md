# Выбор LLM для агента

Агент работает только на моделях с открытыми весами. Доступ к ним на этапе прототипа идёт через OpenRouter.

## Почему открытые веса

Жюри спрашивает, какие модели использовались и можно ли реально применять их в бизнесе. Для сервиса, который работает в России, у закрытых API (GPT, Claude, Gemini) три проблемы:

- персональные данные путешественников уходят за рубеж, а это конфликтует с требованиями 152-ФЗ о локализации;
- доступ к сервису и оплата зависят от внешнего провайдера и санкционных рисков;
- нельзя контролировать версию модели: провайдер может её обновить или отключить.

Открытые веса снимают все три проблемы. Модель можно развернуть в своём контуре (российский ЦОД, vLLM), данные остаются внутри, версия зафиксирована.

## Почему OpenRouter на этапе прототипа

- Один OpenAI-совместимый API ко многим open-weights моделям: можно быстро сравнить кандидатов, не поднимая GPU.
- В коде агента используется OpenAI-совместимый клиент, поэтому переезд на self-hosted vLLM сводится к замене `base_url` и ключа.
- В запросах включаем provider routing с `data_collection: "deny"`, чтобы провайдеры не сохраняли запросы.

OpenRouter — инструмент прототипа, а не продовая архитектура. Это нужно прямо проговорить на демо.

## Критерии отбора

1. Веса опубликованы на HuggingFace (у модели в OpenRouter есть `hugging_face_id`). Модели вроде `qwen3.8-max`, `qwen3.7-plus` и `qwen3.8-omni-flash` в OpenRouter выглядят как опенсорс, но на деле это закрытые API Alibaba. Их не берём.
2. Поддерживается tool calling: агент вызывает инструменты поиска отелей, перелётов, погоды и корзины.
3. Лицензия разрешает коммерческое использование без оговорок: MIT или Apache 2.0.
4. Модель хорошо работает с русским языком (проверяем своим прогоном, см. ниже).
5. Цена и скорость подходят для диалога.

## Кандидаты

Данные из каталога OpenRouter и HuggingFace API на 2026-10-23.

| Роль | Модель в OpenRouter | Веса на HuggingFace | Лицензия | Цена, $ за 1M токенов (вход / выход) |
|---|---|---|---|---|
| Основной агент | `deepseek/deepseek-v4.1-flash` | `deepseek-ai/DeepSeek-V4.1-Flash` | MIT | 0.30 / 1.20 |
| Запасная, сравнение | `z-ai/glm-5.3-flash` | `zai-org/GLM-5.3-Flash` | MIT | 0.15 / 0.50 |
| Лёгкие задачи: разбор запроса, извлечение параметров | `qwen/qwen3.8-27b` | `Qwen/Qwen3.8-27B` | Apache 2.0 | 0.20 / 2.50 |
| Тяжёлое рассуждение, если Flash не справится | `deepseek/deepseek-v4-pro-0813` | `deepseek-ai/DeepSeek-V4-Pro-0813` | MIT | 0.66 / 1.98 |

`Qwen3.8-27B` отдельно важна для аргумента про бизнес: модель такого размера помещается на одну серверную GPU, и self-hosting становится реальным даже для небольшой команды.

## Не берём без отдельной проверки лицензии

У этих моделей кастомная лицензия (`other` на HuggingFace). Там возможны ограничения на коммерческое использование, на число пользователей или на сферы применения.

| Модель | Лицензия |
|---|---|
| `zai-org/GLM-5.3` (полная версия) | `glm-5.3` |
| `Qwen/Qwen3.8-Flash-Next` | `qwen-community-1.0` |
| `MiniMaxAI/MiniMax-M3.1-Flash` | `minimax-community` |
| `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16` | `openmdw-1.1` |
| `meta-models/Muse-Spark-Open-816B-A42B` | `muse-model-license`, доступ к весам по ручному одобрению |

## Что ещё не проверено

Качество русского языка и стабильность вызова инструментов в наших сценариях пока не замерены, выше только данные каталога. Окончательный выбор делаем после прогона кандидатов на наборе из 10–15 тестовых запросов. Смотрим на:

- корректность вызовов инструментов (валидный JSON, правильные аргументы);
- число лишних уточняющих вопросов;
- ошибки в состыковках (даты, время прилёта и заселения);
- время до первой рекомендации и стоимость сценария.

Этот же прогон закрывает дополнительную задачу про метрики качества агента.
