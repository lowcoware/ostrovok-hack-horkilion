# ADR 0003. Визы по гражданству: все страны с пометкой визы вместо «только Россия и безвиз»

- Статус: proposed
- Дата: 2026-10-25
- Дополняет: [ADR 0001](0001-architecture.md) (источники данных, пример про визу в Турцию), [ADR 0002](0002-reusable-agent-platform.md) (контракты поставщиков)
- Связанные документы: [спека 0002](../specs/0002-visa-and-citizenship.md), [roadmap](../roadmap.md), [спецификация продукта](../spec.md)

## Контекст

В решениях по объёму стояло: география — Россия и безвизовые для граждан России страны (`spec.md`, раздел 2; `roadmap.md`, «Что решено»). Это же ограничение зашито в контракт: `catalog.v1.SearchDestinationsRequest.russia_and_visa_free_only`.

Команда меняет объём (2026-10-25):

- подбираем направления по всем странам, у визовых стран показываем пометку: нужна ли виза и какая;
- виза зависит от гражданства путешественника, а не от того, откуда он летит. Гражданин Беларуси, который летит из Минска в Пекин, и гражданин России из Москвы в Пекин получают ответ по своему паспорту;
- пользователь выбирает гражданство и город отправления, по умолчанию — Россия.

Причина в переиспользуемости, первом критерии оценки: у Островка есть клиенты не только с российским паспортом, и агент, который умеет только «Россия плюс безвиз для граждан РФ», бизнесу придётся переписывать.

Данные есть. Набор `imorte/passport-index-data` (MIT, обновлён 2026-02-17) — продолжение архивированного `ilyankou/passport-index-dataset` из ADR 0001. В нём матрица 199 паспортов на 198 стран со статусом `visa free` (с числом дней), `visa on arrival`, `eta`, `e-visa`, `visa required`, `no admission`. Проверено 2026-10-25: для паспорта РФ 79 стран без визы, 27 с визой по прилёту, 24 с электронной визой, 8 с электронным разрешением, 60 с визой.

## Решение

1. **Гражданство — часть ограничений поездки.** В `TripPlan.constraints` появляется `citizenship` (ISO 3166-1 alpha-2, по умолчанию `RU` как видимое допущение). Город отправления остаётся в `origin`, страна отправления выводится из него и в визовом решении не участвует.
2. **Визовый режим — справочник поставщика `catalog`.** Новые RPC: `GetVisaRequirement` (паспорт, страна) и `ListCountries`; `Destination` несёт поле `visa`. Агент и фронт визы сами не вычисляют.
3. **Источник — матрица passport-index-data**, сверка с whereTOemigrate (CC BY 4.0). Для граждан России популярные направления сверяются со справкой Консульского департамента МИД; расхождения правятся поверх матрицы отдельным файлом, а у записи в `sources` появляется второй источник `mid-ru` с полем `field_scope: "visa"`.
4. **Подбор направлений показывает все страны.** Фильтр «только без визы» (`preferences.visa_free_only`) включён по умолчанию; агент снимает его, если пользователь сам назвал визовую страну или просит «можно и с визой». Без визы считаются `visa free` и `visa on arrival`; `eta` и `e-visa` помечаются как оформляемые онлайн.
5. **Виза проверяется в плане как стыковка.** Новые проверки в `TripPlan.checks`: `visa` (нужна ли виза в страну назначения) и `stay_within_visa_free_days` (поездка укладывается в безвизовый срок). Проверка `fail` не блокирует покупку, но агент обязан о ней сказать.

## Рассмотренные альтернативы

| Вариант | Почему нет |
|---|---|
| Оставить «Россия и безвиз» из ТЗ | бизнес с иностранными клиентами не переиспользует агента; первый критерий оценки |
| Визы по стране отправления | неверно по сути: виза зависит от паспорта, гражданин Беларуси, живущий в Москве, получил бы ответ для граждан России |
| Скрывать визовые страны, пока пользователь не попросит | вдохновение теряет половину направлений; пометка на карточке честнее скрытия |
| Свой справочник виз, собранный вручную | 199 × 198 пар руками не собрать за неделю; ручная работа идёт только на сверку популярных направлений |
| Запрашивать визовый режим у LLM | модель ошибается и не даёт источника; в `sources` нечего показать |

## Последствия

- Контракт меняется до начала работы треков фазы 1: OpenAPI, `common.v1`, `catalog.v1`, фикстура моков. Спека 0002 описывает изменения, первый PR фазы 1 правит контракт и обе его стороны, как требует roadmap.
- `russia_and_visa_free_only` удаляется из `catalog.v1` (поле 9 резервируется).
- География шире: каталог направлений, отели, транспорт и трансферы нужны и для зарубежных стран. Объём данных растёт; поэтому каталог направлений — курируемый список, а не вся планета (спека 0003, задача данных).
- Цены остаются в рублях. Для зарубежных направлений нужен пересчёт по курсу ЦБ РФ, источник уже в списке (`spec.md`, раздел 6).
- Визовые данные устаревают. Дата обновления видна на странице «Откуда данные»; в демо говорим, что визовый режим справочный и перед поездкой его надо проверить на сайте посольства.
- Транзитные визы при пересадках в третьей стране не проверяем (спека 0002, Non-Goals).
- ADR 0001, раздел «Нестандартные запросы»: пример «а сколько стоит виза в Турцию?» остаётся `off_topic` для стоимости, но факт «нужна ли виза» агент теперь берёт из справочника.
