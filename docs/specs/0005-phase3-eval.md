# Спека 0005. Фаза 3: eval и качество агента — разбивка по ролям

- Статус: inbox
- Дата: 2026-10-26
- Основание: [roadmap](../roadmap.md), фаза 3; [`spec.md`](../spec.md), раздел 7 «Качество агента»; [кейс](../case.md), дополнительная задача «Метрики качества агента»
- Ревью: Ask. Формат набора и отчёта ревьюят DS, BE и FE вместе до начала `P3-DS-01`.

## Context

Кейс просит собственный набор тестовых запросов и замеры: доля доведённых до конца сценариев, число уточнений, время до первой рекомендации, ошибки в стыковках. На защите жюри даёт агенту запросы, которых команда не видела, поэтому eval — это ещё и способ найти провалы до защиты. До 2026-10-26 eval был в фазе 2; вынесен отдельно, потому что он проверяет весь путь и имеет смысл только после фаз 1 и 2.

## Цель фазы

1. Одна команда `./run.sh eval` прогоняет набор против запущенного стека и пишет отчёт в `eval/reports/`.
2. Отчёт содержит четыре метрики кейса по всему набору и по тегам, а также список провалов с причиной.
3. Набор — около 50 случаев: размытые, с несколькими намерениями, с изменением условий, вне темы, с иностранным гражданством и визовыми странами, с попыткой промпт-инъекции.
4. На сайте есть страница метрик агента, которая показывает последний отчёт.
5. Провалы dev-части набора разобраны: исправлены или записаны как известные ограничения в README.

## Non-Goals

- LLM-судья качества текста ответа: проверяем итоговое состояние плана и корзины (методика τ²-bench), а не стиль.
- Нагрузочное тестирование.
- Прогон в CI на каждый PR: прогон с LLM платный и медленный, запускается руками и в фазе 4.

## Контракт

### CFC-11. Набор eval: DS → BE

Файлы `eval/cases/<id>.yaml`, один случай на файл. Части набора: `dev` (около 40, на них чинят агента) и `holdout` (около 10, их до фазы 4 не открывает никто, кроме DS).

```yaml
id: sea-november-kids
split: dev                # dev | holdout
tags: [vague, kids, sea]  # vague, multi_intent, change, off_topic, foreign_citizen, visa, injection
turns:                    # сообщения пользователя по порядку; patch — правка из интерфейса
  - message: "хочу к тёплому морю в ноябре, недорого, с ребёнком, без долгих перелётов"
  - answer_clarify: first # ответить на уточнение первым быстрым ответом, если оно есть
  - select: recommended   # выбрать рекомендованное направление и варианты
  - message: "а если на два дня позже"
  - checkout: true
expect:
  stage: checkout          # этап, до которого сценарий должен дойти
  constraints:             # подмножество Constraints итогового плана
    child_ages_len: 1
    preferences.moods: [sea, warm]
  destination:
    tags_any: [sea]
    visa_status_in: [home, visa_free, visa_on_arrival]
  components: [outbound, return, stay, transfer_arrival, transfer_departure]
  checks_without_fail: true
  order: paid             # paid | none
  max_clarifications: 2
```

- Для `off_topic` и `injection` ожидание — `order: none` и неизменные правила: цены и итог считаются кодом, а не текстом пользователя.
- `sources` для eval не нужны: случаи пишет команда, они не данные снапшота.

### CFC-12. Отчёт eval: BE → FE

`eval/reports/<дата-время>.json` и `eval/reports/latest.json`; рядом `.md` для чтения людьми.

```json
{
  "run_at": "2026-10-28T10:00:00Z",
  "commit": "abc1234",
  "llm_model": "…",
  "split": "dev",
  "metrics": {
    "completion_rate": 0.86,
    "clarifications_avg": 1.2,
    "time_to_first_recommendation_ms_p50": 4200,
    "connection_errors_rate": 0.02
  },
  "by_tag": {"visa": {"completion_rate": 0.8}},
  "cases": [{"id": "…", "passed": false, "failed_expect": ["checks_without_fail"], "trace_url": "…"}]
}
```

- `GET /api/v1/agent-metrics` отдаёт `latest.json` без `trace_url`, если Langfuse не публичный. Нет отчёта — `404`.
- Метрики считаются так: доведён до конца — выполнены все `expect`; уточнения — число событий `clarify`; время до первой рекомендации — от отправки первого сообщения до первого события `plan` с вариантами направлений или компонентов; ошибки в стыковках — доля случаев, где в итоговом плане есть проверка со статусом `fail`, не ожидаемая случаем.

## Риски

- **Прогон с LLM стоит денег и времени.** Прогонщик ограничивает параллельность и общий бюджет токенов флагом; без ключа прогон идёт на правилах и всё равно даёт метрики.
- **Подгонка под набор.** Holdout не открывается до фазы 4; итоговые числа для README берутся по holdout.

## Decision Log

- **Проверка итогового состояния, а не текста.** Итог проверяется кодом и воспроизводимо; методика τ²-bench (`spec.md`, раздел 6).
- **Случаи в YAML в репозитории.** Их читают люди на защите и правит DS без кода.
