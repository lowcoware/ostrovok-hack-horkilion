# Журнал изменений

Все заметные изменения проекта записываются в этот файл.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [Семантического версионирования](https://semver.org/lang/ru/spec/v2.0.0.html).

## [Unreleased]

### Добавлено

- Прототип агента путешествий: чат, план поездки с вариантами отелей, погода и имитированная покупка.
  Технически: Go-сервисы `gateway`, `agent`, `inventory`, `booking`, `notifier`, `migrate`; синхронные вызовы
  по gRPC, ход агента и события бронирования через NATS JetStream (`AGENT_TURNS`, `BOOKINGS`), transactional
  outbox в `booking`; PostgreSQL, Langfuse, Prometheus, Grafana, ClickHouse; фронт React + Vite + Tailwind за
  Caddy; полный стек в `deploy/docker-compose.yml`. (`fccf943`)
- CI и деплой пересобирают только изменённую часть монорепозитория. Технически: задача `changes` в
  `.github/workflows/ci.yml` выдаёт `backend`, `web`, `deploy`; Go-сервисы и фронт деплоятся под разными
  тегами (`BACKEND_TAG`, `WEB_TAG`, файл `.image-tags` на сервере); `VITE_API_TARGET` направляет dev-сервер
  фронта на задеплоенный бэкенд. (`36e5389`)
- Документы проекта: ADR 0002 о переиспользуемости (адаптеры поставщиков, агент как API, аккаунты, запуск для
  жюри), roadmap по фазам, спецификация продукта и спека фазы 0. Технически: `docs/adr/0002-reusable-agent-platform.md`,
  `docs/roadmap.md`, `docs/spec.md`, `docs/specs/0001-phase0-contracts.md`. (`825e2da`, `634c74f`, `2afd094`)
- Внешнее API агента с версией в пути: сессии и список поездок владельца, сообщения, правка плана из
  интерфейса, события хода по SSE, заказ из выбранных вариантов, заказы, «Откуда данные», аккаунт.
  Технически: `api/openapi.yaml` (OpenAPI 3.1, префикс `/api/v1`), схемы `TripPlan` v2, `PlanPatch`,
  `AgentEvent` (`status`, `token`, `plan`, `clarify`, `done`, `error`), ошибки `{"error": {"code", "message"}}`;
  `/auth/register`, `/auth/login`, `/auth/logout` пока отвечают `501`; пакет `api` встраивает спеку для тестов;
  линт — `redocly lint`, правила в `redocly.yaml`. (`29776b5`)
- План поездки v2 из компонентов: транспорт туда и обратно, проживание, два трансфера; у варианта цена,
  объяснение, флаги и источники; проверки стыковок, конфликты, итог и превышение бюджета. Технически:
  пакет `internal/agent/plan`, таблица инвалидации из ADR 0001 в `Apply`; выбор варианта и правки карточек
  идут через `POST /api/v1/sessions/{id}/plan` тем же механизмом, что и сообщения. (`29776b5`, `5e6b0c4`)
- Контракты поставщиков v2 и поле происхождения данных `sources` у всех сущностей. Технически:
  `proto/common/v1` (`Source`, `GeoPoint`, `Place`, `Travelers` с возрастом детей), `catalog/v1`, `lodging/v1`,
  `transport/v1`, `transfer/v1`; `booking/v1` с позициями заказа и деталью ошибки `PriceChanged`;
  генерация всех файлов `proto/` скриптом `scripts/gen-proto.sh` (protoc 36.2). (`29776b5`)
- Выбор реализации поставщика в конфиге: неизвестное значение останавливает процесс со списком допустимых.
  Технически: `CATALOG_PROVIDER` (`open-data`), `LODGING_PROVIDER` (`synthetic`), `TRANSPORT_PROVIDER` и
  `TRANSFER_PROVIDER` (`stub`, отвечают `UNIMPLEMENTED` до фазы 1); `platform.Provider`; все четыре сервиса

- Контракт виз и гражданства (`P1-BE-01`): у направлений и в плане видно, нужна ли виза, по гражданству
  путешественника. Технически: OpenAPI — `VisaStatus`, `VisaRequirement`, `Country`, `Constraints.citizenship`,

  гражданства сбрасывает варианты направлений и визу, отели не трогает. (`406708b`)

  снапшот останавливает сервис. Технически: пакет `internal/dataset` — наборы CFC-3, `manifest.json` с

  passport-index-data, климат Open-Meteo, отели OSM, тестовые тарифы) лежит в образе `inventory` до появления

- Провайдер `catalog` на снапшоте данных (`P1-BE-03`): подбор направлений с визами по гражданству, справочник
  стран, подсказки городов. Технически: `ListCountries` (Россия первой), `GetVisaRequirement` (`INVALID_ARGUMENT`
  для неизвестных кодов, `NOT_FOUND` для пары без данных, своя страна — `home`), `SearchPlaces` (города по началу
  русского или английского названия, аэропорты по запросу), `SearchDestinations` (теги, бюджет, максимум часов в

  провайдеров на данных (CFC-5). (`7aa2ade`)
- Провайдер `lodging` на отелях OpenStreetMap (`P1-BE-04`): настоящие отели из снапшота с синтетическими ценой
  и условиями, туристический налог в цене. Технически: провайдер `osm` — звёзды, питание, отмена и животные
  генерируются от `id` отеля, цена от веса гостей, звёзд, страны, сезона и даты, надбавка за животное, налог по
  `calibration` входит в `total_price_rub`; источники `osm` и `synthetic`; `LODGING_PROVIDER` по умолчанию
  `osm`, `synthetic` остаётся вторым адаптером контракта. (`e0a3f90`)
- Провайдер `transport` `synthetic` (`P1-BE-05`): рейсы и поезда между городами каталога с ценой и временем.
  Технически: рейсы по маршрутам снапшота (1–3 вылета в день, перевозчик по стране вылета, пересадка через аэропорт
  снапшота с наименьшим крюком, не длиннее прямой на 30%, стыковка из `calibration`), время RFC 3339 в поясе
  места, тарифы по правилам `internal/synth`; поезда по расписанию снапшота в обе стороны; `id` поездки кодирует
  маршрут, дату и вылет, `GetOffer` пересобирает ту же поездку; в `internal/dataset` поиск маршрутов в обе
  стороны и городов по имени, коду аэропорта или вокзала; встроена `time/tzdata` (образ `FROM scratch`);
  `TRANSPORT_PROVIDER` по умолчанию `synthetic`. (`f49bafd`)
- Провайдер `transfer` `synthetic` (`P1-BE-06`): такси, шаттл и общественный транспорт между аэропортом или
  вокзалом и отелем. Технически: такси и общественный транспорт для любой пары, шаттл — от аэропорта до отеля не
  дальше 60 км и без животных; дорога в 1,3 раза длиннее прямой, время и цена по правилам `internal/synth`, с
  животным такси дороже; места ищутся по `id` снапшота (IATA, код вокзала, `id` отеля), `depart_at` в поясе
  места отправления; `id` трансфера кодирует вид, оба места и время, `GetOffer` пересобирает то же
  предложение; `TRANSFER_PROVIDER` по умолчанию `synthetic`. (`e8f80f4`)
- Сборка полной поездки и валидатор стыковок (`P1-BE-07`): агент за один ход собирает отель, дорогу туда и обратно
  и оба трансфера, проверяет визу и стыковки. Технически: шаг `assemble` ищет или перепроверяет компоненты по
  порядку поездки, новый поиск отеля или дороги пересобирает зависящие трансферы; поездка собирается из выбранного
  варианта или первого, пока пользователь не выбрал (дорога туда — сначала прибытие в день заселения, потом цена и
  время); трансфер к отправлению подбирается по каждому виду так, чтобы приехать за буфер из `config/rules.yaml`;
  проверки `arrival_before_checkin`, `transfer_fits`, `checkout_before_departure`, `dates_consistent`; виза через
  `GetVisaRequirement` по стране направления; выбор дороги или отеля перепроверяет трансферы; `agent.New`
  принимает `Suppliers` с клиентами `transport` и `transfer`. (`e0b6260`)
- Подбор направлений в агенте (`P1-BE-08`): без названного направления агент предлагает до пяти вариантов с
  объяснением, минусами и рисками, выбор — сообщением, номером варианта или патчем `destination`. Технически:
  `SearchDestinations` с городом отправления, датами, составом, настроениями как тегами, бюджетом, часами в пути,
  гражданством и `visa_free_only`; меньше трёх результатов — повтор без бюджета и времени в пути, минусы это
  называют; объяснения на правилах в `plan.SetDestinationOptions`; гейт `inspire`; роутер узнаёт вариант по
  порядковому номеру или основе названия в любом падеже, промпт LLM-роутера получает список вариантов; событие
  `clarify` предлагает названия как быстрые ответы. (`078ab67`)
- Новые поля роутера (`P1-BE-10`): город отправления, гражданство, месяц поездки, настроения, виды транспорта,
  часы в пути, строгость бюджета и «можно с визой» понимаются из сообщения. Технически: правила для фраз «из
  Минска», «у меня паспорт Беларуси», «в ноябре», «к тёплому морю», «поездом», «не больше 4 часов», «без долгих
  перелётов», «строго 100 тысяч», «виза не проблема»; толкования (начало месяца, до 5 ч в пути) становятся
  допущениями через `plan.Patch.Assumed`; агент приводит город отправления и направления к названию из каталога
  через `SearchPlaces`; промпт LLM-роутера с теми же полями. (`ad96015`)
- Справочники в gateway (`P1-BE-11`): `GET /countries` для выбора гражданства и `GET /places` для подсказок
  города отправления. Технически: прокси к `catalog.ListCountries` и `catalog.SearchPlaces`, `query` от 2 до 100
  символов и `kind=city`, иначе `400`; gateway подключается к `INVENTORY_ADDR`, `gateway.New` принимает
  `Deps`. (`cfe8f2c`)

### Изменено

- План проекта перестроен под три роли и новую географию. Технически: `docs/roadmap.md` и `docs/spec.md` —
  роли бэкенд, данные и фронт вместо треков A, B, F; этап 1.0 «контракт виз» в фазе 1; визы в фазах 2 и 3;
  открытые вопросы Q-005…Q-007; датированные дополнения в ADR 0001, ADR 0002 и спеке 0001. (`9fa52c0`)

- Агент, фронт и gateway перешли на контракт фазы 0: план v2, события в конверте и API `/api/v1`.
  Технически: событие SSE — `{"type", "session_id", "turn_id", "seq", "data"}`, `turn_id` равен `message_id`
  из ответа `202`; TS-типы генерируются `npm run gen:api` (openapi-typescript 7.13 на TypeScript 5.9 через
  `npx`, в проекте TypeScript 7). (`29776b5`, `5e6b0c4`)
- LLM-провайдер настраивается переменными для любого OpenAI-совместимого эндпоинта. Технически:
  `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_ROUTER_MODEL`, `LLM_EXTRA_BODY` (JSON, по умолчанию
  `{"provider":{"data_collection":"deny"}}`); неверный JSON — ошибка запуска. (`29776b5`, `f5ee3a4`)
- Синтетические отели учитывают возраст детей, питание передаётся кодами, у отеля место, время заезда и
  условия отмены. Технически: младенцы до 2 лет бесплатно, дети до 12 лет — половина цены; `meal` —
  `room_only`, `breakfast`, `half_board`, `all_inclusive`; фильтры поиска в `lodging.v1.Filters`. (`29776b5`)
- Мессенджеры исключены из объёма, мобильная версия — адаптивный сайт, уведомления показываются на сайте.
  Технически: правки ADR 0001, README и комментариев в `gateway` и `notifier`. (`825e2da`)
- Событие о созданном заказе несёт позиции заказа. Технически: полезная нагрузка `booking.created` —
  `platform.BookingCreated` (`id`, `session_id`, `owner_id`, `total_rub`, `items`). (`29776b5`)
- Город отправления по умолчанию — Москва, видимое допущение `origin`, пока пользователь не назвал другой.
  Технически: `plan.FillDefaults`, константа `DefaultOrigin`. (`e0b6260`)
- Страница «Откуда данные» строится из реестра `sources.yaml` снапшота данных, а не из списка в коде.
  Технически: `GET /sources` отдаёт провайдеров со `status: used`, описание собирается из `kind` и
  `used_for`; gateway читает снапшот из `DATA_DIR` и проверяет его через `dataset.Load`. (`cfe8f2c`)

### Устарело

- Переменная `OPENROUTER_API_KEY`: используйте `LLM_API_KEY`. Технически: читается как запасное имя ключа,
  если `LLM_API_KEY` пуст, до конца фазы 1. (`29776b5`)

### Удалено

- API без версии `/api/...`, клиенты переходят на `/api/v1`. Технически: старые сессии без записи в
  `gateway.sessions` отвечают `404`, фронт в этом случае создаёт новую сессию. (`29776b5`, `5e6b0c4`)
- Контракт `inventory.v1`: его RPC разошлись по `catalog.v1` и `lodging.v1`. Технически: удалены
  `proto/inventory/v1` и `gen/inventory/v1`. (`29776b5`)
- Ручные TS-типы ответов API. Технически: удалён `web/src/api.ts`, типы — из `web/src/api/schema.ts`. (`5e6b0c4`)
- Поля отеля у заказов: заказ теперь состоит из позиций. Технически: миграция удаляет у `booking.orders`
  столбцы `hotel_id`, `hotel_name`, `check_in`, `nights`, `adults`, `children`, добавляет `owner_id` и
  `items`, переименовывает `total_price_rub` в `total_rub`; старые заказы без владельца не видны в `/orders`. (`29776b5`)
